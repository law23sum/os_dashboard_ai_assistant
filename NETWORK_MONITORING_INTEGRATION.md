# Network Monitoring Web Integration

## Summary

Network monitoring has been integrated into the OS Dashboard AI Assistant web interface. The system can monitor local networks, detect suspicious devices, and provide real-time network security insights.

## What Was Implemented

### 1. Backend API Router (`backend_api/routers/network_monitoring.py`)

A new FastAPI router that provides:

- **GET `/api/network/status`**: Get complete network monitoring report
  - Parameters: `refresh` (optional) - if True, runs network watch script first
  - Returns: NetworkMonitoringReport with devices, connections, interfaces, WiFi status
  
- **POST `/api/network/refresh`**: Trigger refresh of network data
  - Runs the network_watch.py script to generate fresh data
  
- **GET `/api/network/devices`**: Get simplified device list
  - Returns just the devices with suspicious device count
  
- **GET `/api/network/interfaces`**: Get network interface statistics
  - Returns interface throughput and packet statistics

The router reads from `~/OS_Dashboard_AI_Assistant/logs/network_watch.json` which is generated by the enhanced `network_watch.py` script.

### 2. Frontend React Page (`frontend/src/pages/NetworkMonitoring.tsx`)

A comprehensive network monitoring interface featuring:

- **Device Monitoring Table**: Shows all network devices with:
  - IP address, MAC address, hostname
  - Interface information
  - Known/Suspicious/Unknown status indicators
  
- **Suspicious Device Alerts**: Highlighted alerts for suspicious devices with:
  - Severity levels (low/medium/high)
  - Detailed suspicious reasons
  - Visual indicators
  
- **Summary Cards**: Quick overview metrics:
  - Total devices
  - Suspicious device count
  - Authentication failures
  - Listening ports
  
- **Network Interfaces**: Real-time interface statistics:
  - Transmit/Receive speeds (Mbps)
  - Packet rates
  - Per-interface breakdown
  
- **WiFi Status**: Current WiFi connection information:
  - SSID, channel, signal strength
  
- **Auto-refresh**: Optional automatic refresh every 10 seconds
- **Manual Refresh**: Trigger immediate data refresh
- **Network Scope Selector**: Switch between Local/WAN/All networks (UI ready, backend extensible)

### 3. Routing Integration

- **Route**: `/systems/network` and `/network`
- **Navigation**: Added to "Execution Surfaces" menu under Systems
- **Icon**: Network icon from lucide-react

## Features

### Universal Network Access

The system is designed to be **generic and extensible**:

1. **Network Scope Parameter**: The UI includes a selector for Local/WAN/All networks
   - Currently defaults to local network
   - Backend can be extended to filter by network scope
   - Future: Add remote network monitoring via SSH/API

2. **Flexible Device Detection**: 
   - Works with any network the script can access
   - Reads from ARP tables (universal)
   - Can be extended to SNMP, mDNS, etc.

3. **Configurable Monitoring**:
   - Network watch script can be configured for different networks
   - Script accepts parameters for custom monitoring
   - JSON output is standardized regardless of source

### Security Features

- **Suspicious Device Detection**: Automatically flags:
  - Devices with suspicious hostname patterns (VPS identifiers, cloud instances)
  - Unknown devices not in known devices list
  - Devices with incomplete MAC addresses
  
- **Authentication Monitoring**: Tracks failed login attempts
  
- **Connection Analysis**: Monitors suspicious outbound connections

- **Real-time Alerts**: Visual alerts for suspicious activity

## Usage

### Accessing the Page

1. Navigate to **Systems → Network Monitoring** in the sidebar
2. Or directly visit `/systems/network` or `/network`

### Using the Interface

1. **View Current Status**: Page loads automatically with latest network data
2. **Refresh Data**: Click "Refresh" button to run network scan
3. **Auto-refresh**: Enable "Auto" button for continuous monitoring (updates every 10s)
4. **Review Suspicious Devices**: Check highlighted alerts at top of page
5. **Monitor Interfaces**: Scroll to see network interface statistics

### Backend Configuration

The backend reads from:
- `~/OS_Dashboard_AI_Assistant/logs/network_watch.json` - Main report data
- `~/OS_Dashboard_AI_Assistant/logs/known_devices.json` - Trusted devices list

Ensure the network watch script has been run at least once:
```bash
python3 ops_root_assets/scripts/network_watch.py
```

## API Endpoints

All endpoints are under `/api/network/`:

- `GET /api/network/status?refresh=false` - Get network status
- `POST /api/network/refresh` - Trigger data refresh
- `GET /api/network/devices?refresh=false` - Get device list
- `GET /api/network/interfaces?refresh=false` - Get interface stats

## Testing

To test the integration:

1. **Start the backend**:
   ```bash
   cd backend_api
   python main.py
   ```

2. **Run network watch script** (if not already done):
   ```bash
   python3 ops_root_assets/scripts/network_watch.py
   ```

3. **Start the frontend**:
   ```bash
   cd frontend
   npm run dev
   ```

4. **Access the page**:
   - Navigate to Systems → Network Monitoring
   - Or visit `http://localhost:5173/systems/network`

5. **Verify functionality**:
   - Check that devices are displayed
   - Test refresh button
   - Verify suspicious device alerts (if any)
   - Check interface statistics

## Dependencies

- **Backend**: FastAPI, Pydantic
- **Frontend**: React, TanStack Query, lucide-react icons
- **Network Script**: Python 3, psutil, subprocess

## Notes

- The network monitoring script must have appropriate permissions to read ARP tables
- On macOS/Linux, may require sudo for full network access
- The known_devices.json file is created automatically on first run
- Network data is cached in JSON file between script runs for performance
